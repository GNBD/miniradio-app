GNBD MINI-RADIO COMPANION APP - FULL FEATURE DESIGN
=====================================================

Project : extfirm/app  (Flutter + Dart)
Target  : Android 8.0+ (minSdk 26), iOS later
Firmware: miniradio 1.2.27 (BLE not yet present) -> 1.3.x (BLE added)
Status  : DESIGN ONLY. No implementation in this document.
Date    : 2026-11-04


---------------------------------------------------------------------------
0. GOAL
---------------------------------------------------------------------------
The radio is an ESP32-S3 + SI4732 receiver with a small display. It has no
keyboard, no rich UI, and (when Wi-Fi is off) no internet path.

The companion app provides:
  - Remote control of the radio over BLE (tuning, volume, bands, presets).
  - A network bridge: the phone performs HTTP requests on behalf of the
    radio when the radio has no Wi-Fi.
  - Notification mirror: phone notifications appear on the radio display
    as a OneUI-style animated toast.
  - Quick replies and a keypad on the radio for incoming messages.
  - Settings, firmware update, and diagnostics surfaces.


---------------------------------------------------------------------------
1. PRODUCT PRINCIPLES
---------------------------------------------------------------------------
P1  EASY. Every screen has one primary action. No nested menus deeper
    than 2 levels. A first-time user must reach "tune the radio" in
    under 10 seconds after connecting.
P2  LIGHT. App size target < 25 MB APK. Idle BLE scan duty cycle keeps
    the phone battery impact negligible. No background services other
    than the BLE connection itself.
P3  RADIO FIRST. The radio stays usable without the phone. The app is
    never required for normal listening; it only adds capability.
P4  BRIDGE ON DEMAND. When radio Wi-Fi is available the radio uses it
    directly. The phone bridge is used only when the radio explicitly
    requests it (BLE link up, radio Wi-Fi down or not configured).
P5  ONE LINK. Exactly one active connection at a time. The app connects
    to one radio; the radio accepts one central.
P6  FAIL SOFT. Any dropped link degrades to local-only control (phone
    keeps last known state, shows "disconnected" banner, retries).
P7  LOCALISABLE. All user-facing strings go through the i18n table from
    day one. Noto Sans (subset) is used on the radio for non-ASCII text.

3. BLE GATT PROTOCOL (radio = peripheral, app = central)
---------------------------------------------------------------------------
Service UUID : 0000a1b1-0000-1000-8000-00805f9b34fb  (MNRC = MINiRadio)
App must request MTU 245 (negotiated, fallback 185).
All multi-byte integers are little-endian. Strings are UTF-8, no NUL
terminator, length implied by payload.

Characteristics:
  CTRL   0000a1b2-...-fb   write / notify     command + ack
  EVENT  0000a1b3-...-fb   notify             unsolicited radio events
  BRIDGE 0000a1b4-...-fb   write / notify     HTTP bridge request/response
  STATE  0000a1b5-...-fb   notify             periodic full state snapshot

3.1 CTRL command frame (app -> radio)
    [ver:1][seq:1][cmd:1][argc:1][args...]
    ver  = 0x01
    seq  = echoed in the ACK; used to match request/response
    ACK  (radio -> app)  [ver][seq][status:1][len:1][payload]
    status 0=OK, 1=BAD_ARG, 2=BUSY, 3=UNSUPPORTED, 4=STATE

    cmd  Name                args
    0x01 TUNE_ABS            [freq_hz:4]
    0x02 TUNE_STEP           [steps:1 signed]  (encoder emulation)
    0x03 SEEK                [dir:1]  0=down 1=up
    0x04 BAND_SELECT         [band_idx:1]
    0x05 MODE_SELECT         [mode:1]  0=FM 1=AM 2=SSB ...
    0x06 VOLUME_SET          [vol:1]  0..63
    0x07 BW_SET              [bw_idx:1]
    0x08 AGC_SET             [on:1][agc_idx:1]
    0x09 SQUELCH_SET         [on:1][level:1][type:1]
    0x0A PRESET_LIST         []  -> ACK payload = count then entries
    0x0B PRESET_SAVE         [slot:1][freq_hz:4][band:1][mode:1]
    0x0C PRESET_DELETE       [slot:1]
    0x0D PRESET_TUNE         [slot:1]
    0x0E FAVORITE_LIST       []  -> same encoding as PRESET_LIST
    0x0F KEY_INPUT           [key:1]  (keypad on radio, from quick reply)
    0x10 REPLY_SEND          [idx:1]  (send quick reply index)
    0x11 NOTIFY_DISMISS     []       (hold-to-dismiss on radio)
    0x12 PING                []       (link keepalive, 15 s)
    0x13 GET_INFO            []       -> fw ver, chip id, battery, rssi
    0x14 BRIDGE_ENABLE       [on:1]   (phone starts serving requests)
    0x15 STREAM_START        [fmt:1]  (0=pcm16 mono 16k, reserved)
    0x16 STREAM_STOP         []
    0x17 OTA_BEGIN           [size:4][sha256:32]
    0x18 OTA_DATA            [chunk:4][bytes:n]
    0x19 OTA_END             []

3.2 EVENT notifications (radio -> app)
    [ver][evt:1][len:1][payload]
    0x01 STATE_CHANGED   full state (same layout as STATE char)
    0x02 TUNED           [freq_hz:4][band:1][mode:1]
    0x03 PRESET_CHANGED  [op:1][slot:1]
    0x04 NOTIFICATION    [id:2][src:1][title_len:1][body...]
    0x05 REPLY_REQUESTED [id:2][quick_count:1][labels...]
    0x06 BRIDGE_REQUEST  (see 3.3)
    0x07 STREAM_STATUS   [state:1][underruns:2]
    0x08 OTA_PROGRESS    [pct:1]
    0x09 LINK_LOSS_WARN  [seconds:2]  (radio about to sleep Wi-Fi/BLE)

3.3 BRIDGE flow (phone does HTTP for the radio)
    Radio -> app : BRIDGE_REQUEST  [req_id:2][method:1][url_len:1][url]
                   [hdr_len:1][body_len:2][body]
                   method 1=GET 2=POST
    App -> radio : write BRIDGE   [req_id:2][status:2][ctype_len:1]
                   [ctype][body_len:2][body]
    App performs the request with dio, returns result. Radio treats
    non-2xx as status pass-through. Timeout on radio: 15 s.
    Known radio-originated requests (firmware today):
      - http://wttr.in/?format=...            (weather)
      - http://www.eibispace.de/dx/eibi.txt   (EIBI schedule)
      - SNTP (handled by phone clock instead: radio sends time sync
        request, app replies with unix time - cheaper than bridging UDP)
      - OTA manifest check (docs/manifest.json) -> app can hand the radio
        a pre-fetched manifest through BRIDGE.
    Bridge is enabled only while: BLE connected AND radio Wi-Fi down.

3.4 STATE payload layout (also used by /api/status parity)
    freq_hz:4, band_idx:1, mode:1, stereo:1, rssi:1, snr:1, volume:1,
    bw_idx:1, agc_on:1, squelch_on:1, preset_count:1, fav_count:1,
    flags:1  (bit0=wi-fi up, bit1=bridge on, bit2=streaming,
              bit3=charging, bit4=low-battery)
    Radio pushes STATE every 2 s while connected, and immediately after
    any CTRL command that changes it.

4. APP SCREENS & FLOWS
---------------------------------------------------------------------------
S1  Onboarding (3 pages): permission explain (BLE, notifications),
    "scan for radio" call to action, pairing helper.
S2  Scan / Connect: live device list with name (MNRC), RSSI, last-seen.
    Auto-reconnect to last device on app open (P6).
S3  Dashboard (root): large frequency readout, band chip, signal bar,
    volume slider, seek buttons, preset strip (horizontally scrollable).
S4  Presets: grid of 99 slots, long-press to save/edit name, swipe to
    delete with confirm. Mirrors radio FAVORITES list.
S5  Bands & Modes: band chips + mode segmented control + bandwidth /
    AGC / squelch advanced sheet.
S6  Remote keypad: numeric entry (MW/SW direct entry), matches radio
    HMI_KEYPAD semantics.
S7  Bridge status: shows radio Wi-Fi state, requests served this
    session, last error, toggle "enable bridge".
S8  Notifications: list of mirrored notifications, quick-reply actions,
    "dismiss on radio" button.
S9  Stream: starts STREAM_START, plays PCM (raw, light) with a minimal
    play/pause page - no fancy visualizer in v1 (P2).
S10 Settings: language, theme, connect-on-start, notification source
    filter, about (fw version, build, license notices).
S11 Firmware update: fetch manifest, show changelog, OTA over BLE
    (0x17..0x19) with progress bar; also exposes classic Wi-Fi OTA link
    when radio is online.

Flow notes:
  - Dashboard is reachable in one tap from anywhere (bottom nav).
  - Every command optimistically updates UI, reconciled by ACK/STATE.
  - Disconnect banner persists until reconnected; no modal dialogs for
    routine errors (P1).


---------------------------------------------------------------------------
5. NOTIFICATION MIRROR + RADIO TOAST (firmware side, 1.3.x)
---------------------------------------------------------------------------
A1  Phone sends EVENT 0x04 with notification id, source and text.
A2  Radio shows a OneUI-style toast at the TOP of the display:
    - slide-down + fade-in animation (~300 ms)
    - auto-hide after 5 s (TOAST_NG = 5000, distinct from the existing
      TOAST_TIME=2000 center toast used for status messages)
    - background rounded panel, source icon glyph, title + body lines
    - queue depth 3; newest on top, expired items dropped
A3  While a notification is visible:
    encoder click -> quick reply list (up to 5 canned replies) or
                     keypad when the source expects a number
    encoder hold  -> dismiss notification (EVENT 0x11 path)
    BACK          -> dismiss and restore previous screen
    HMI_TUNE conflicts are resolved by giving notification input
    priority ONLY while a notification is on screen (A2 window).
A4  Quick reply selection sends REPLY_SEND; the app performs the actual
    send via the OS (S8) because Android restricts background replies
    without NotificationListenerService access.
A5  Toast rendering must not disturb the radio panel: it overlays the
    top strip and restores the underlying page on expiry
    (page_restore() pattern already exists).
A6  Toast text uses the notification body truncated with ellipsis;
    UTF-8 aware (section 8).
A7  Dismissal on the radio notifies the app (EVENT 0x04 with op=dismiss)
    so the phone list stays in sync.
A8  If BLE drops while notifications are queued, radio drops the queue
    (no stale popups after reconnect).
A9  Do not mirror: ongoing media, silent, and app-whitelisted-out
    notifications (filter lives in S10).


---------------------------------------------------------------------------
6. NETWORK BRIDGE BEHAVIOUR
---------------------------------------------------------------------------
B1  Radio preference "NET": AUTO / WIFI / BRIDGE / OFF.
    AUTO = Wi-Fi if configured and associated, else bridge if BLE up.
B2  Radio marks every outbound HTTP client to consult the bridge when
    its own interface is down: weather, EIBI, OTA manifest. Implementation
    hook: a single `net_fetch()` wrapper in firmware (1.3.x) that picks
    transport.
B3  App caps concurrent bridge requests at 2; queues the rest.
B4  Response size cap 256 KB (EIBI txt ~ 100 KB, fits).
B5  App never sends credentials; radio URLs are plain http only (same
    as today). HTTPS would require the crt bundle on the radio - out of
    scope (P2).
B6  SNTP replacement: radio asks for time (CTRL extension), app replies
    with unix seconds - avoids bridging UDP entirely.


---------------------------------------------------------------------------
7. RADIO INPUT PRIORITY (1.3.x firmware)
---------------------------------------------------------------------------
C1  Priority: notification window (A3) > existing HMI state.
C2  Existing HMI_TUNE behaviour unchanged when no notification:
    click = menu, hold = quick menu.
C3  LIST_IDLE_MS timeout still applies, but a visible notification
    resets the idle timer while displayed.
C4  Encoder fast-repeat during quick reply list uses the existing
    accel_counts() path; no new timing constants.

8. FONTS & INTERNATIONALISATION
---------------------------------------------------------------------------
D1  Radio fonts today: lgfx built-ins (Font0/2/4/6/7, AsciiFont24x48) -
    ASCII only. Korean/Japanese text (notifications, station names)
    cannot render.
D2  Add Noto Sans subset to littlefs partition (0x595000 = 5.6 MB free,
    plenty):
    - Format: lgfx FontConverter output or raw TTF subset (pyftsubset)
      covering: Latin + Hangul (KS X 1001 / 2350 syllables) + kana +
      punctuation. Target < 700 KB per weight.
    - One regular weight for UI text; keep built-in fonts for large
      digits (P7 size budget stays healthy).
    - File: /littlefs/fonts/NotoSansKR-Regular.sub (mounted via
      esp_littlefs, already a managed component).
D3  display.cpp `font_of()` extended: DISPLAY_FONT_TEXT -> Noto subset
    when the string contains non-ASCII, else built-in (zero cost for
    pure-ASCII UI).
D4  Radio strings that become localisable: toast messages, quick reply
    labels, band names, menu entries (menu_data.c table). v1 ships
    EN + KO; string table keyed by ID, language persisted in settings.
D5  App side: flutter_localizations + intl, ARB files ko/en, fallback
    to EN. Same key names as radio IDs where they overlap (P7).
D6  Phone notification text arrives UTF-8; radio must validate and
    replace invalid sequences with '?' before rendering (A6).
D7  Glyph cache: lgfx loads glyphs on demand; cap cache to 256 glyphs
    to bound RAM (ESP32-S3 budget).

9. VERSIONING & RELEASE PLAN
---------------------------------------------------------------------------

    (A1..A9), Noto subset (D2..D4) - each independently verifiable.
E3  Firmware 1.3.0: BLE stack (nimble, lighter than bluedroid), GATT
    server per section 3, STREAM_START reserved.
E4  App 1.0.0: S1..S7 + S10 (control, presets, bridge, settings).
    App 1.1.0: S8 notifications + quick replies.
    App 1.2.0: S9 streaming, S11 OTA.
E5  Compatibility: app 1.x must work with firmware 1.3.0+; CTRL commands
    return UNSUPPORTED (0x03) for unknown cmd so older firmware fails
    soft (P6). App shows "firmware update required" only for commands
    essential to the current screen.
